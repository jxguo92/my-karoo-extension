# Concentric Dashboard 设计访谈

状态：第一轮六项决定已由用户全部确认；正在确认天气来源标注，尚未开始字段实现。按用户指定的 `grill-with-docs` 流程记录。

## 已明确的范围

- 名称为 `Concentric Dashboard`。
- 视觉依据为 [concentric.prototype.html](../../demo/dashboard/concentric/concentric.prototype.html) 的 D / DL，共用布局，分别对应夜间与日间配色。
- 查询 Android `uiMode`，自动切换 light/dark。运行中切换也应刷新；Karoo 是否向扩展传播骑行页主题变化须真机验证。
- 业务规则依据 [context.md](../../demo/dashboard/context.md)；旧 `prototype-description.md` 中的 Karoo 自定义功率区不作为新字段依据。
- 功率外弧只点亮当前区，指针表示 3 秒功率；踏频内弧连续填充，不显示踏频数字。
- 中央显示后拨档位序号、3 秒功率、速度。下方显示距离、心率、坡度、平均速度、平均心率、平均功率、标准化功率。
- 风向、风力配色、静风隐藏、指北针、低速朝向保持、10° 取整均沿用背景文档。
- 原型整屏中的顶部时钟与底部留白是演示外壳，不属于字段内容。
- 术语记录在 [CONTEXT.md](../../CONTEXT.md)。现有 Ladder Full 仅有计划，其专属决策不自动继承。

## 已确认决策（第一轮）

用户已逐项接受以下决定。

1. 布局范围 → 非整页显示与交互：只在 5×2 整页显示，其他尺寸空白且不订阅；无点击动作。
2. 单位 → 速度/距离换算：沿用原型固定公制（km/h、km），不跟随用户单位设置。
3. 分区参数 → 缺失参数行为：用 Karoo 用户资料的 FTP、最大/静息心率计算固定 Coggan/HRR 分区，不读取自定义 zones；资料无效时保留数值，功率不点亮/不画指针，心率用普通文字色，不套用演示参数。
4. 连续边界 → 踏频弧和分区归属：原型踏频填充按 50–110 归一化，背景描述为 51–110；保留原型 50 空、51 开始填充和整数 51–55 第一段。功率/HRR 分区用连续上界比较，边界归较低区，避免百分比区间空隙。
5. 无效与骑行状态 → 独立降级和重置：单项数字 `--`，对应弧保留轨道/刻度但无填充/指针；零功率、速度、踏频有效。暂停继续显示有效值；收到 Idle 全清并重置朝向，Recording/Paused 后恢复。
6. 天气生命周期 → 网络及过期：复用现有和风 provider，首次有位置请求；成功后移动 >5 km 或满30分钟刷新，失败2分钟重试，成功数据超过60分钟隐藏风箭头；无凭据不请求；取消字段时终止任务。
