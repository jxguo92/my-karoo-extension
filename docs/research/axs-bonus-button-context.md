# AXS Bonus Button 按页面/状态执行不同动作：公开 SDK 可行性

调查日期：2026-09-22。范围：本项目使用的 `karoo-ext` 1.1.9、Hammerhead 官方 SDK 文档/样例与 Karoo OS 帮助页。这里的 drawer 指**骑行内抽屉**，不是 Android 应用列表。

## 结论

**前两种效果可以直接得到；“抽屉已打开时，按一次必定收起”无法仅凭公开 `karoo-ext` 1.1.9 可靠实现。** 最简单的方案是将 AXS Bonus Button 在 Karoo 自带的控制配置中直接映射为 **Karoo Button - Upper Right**。右上角实体键本身按当前界面执行相应的导航动作：主屏幕在资料间向右、骑行数据页向右翻页；但抽屉全屏时，左右键切换的是抽屉标签，而不是关闭抽屉。Hammerhead 官方的 AXS 配置列表已包含该硬件键映射，因此这两种需求通常不必由扩展接管。[AXS 控制配置](https://support.hammerhead.io/hc/en-us/articles/25672636525979-Karoo-OS-Controlling-Karoo-with-SRAM-AXS-Controllers)、[Karoo 产品手册的按键上下文](https://support.hammerhead.io/hc/en-us/article_attachments/25673969211803)、[骑行内抽屉操作](https://support.hammerhead.io/hc/en-us/articles/25642872519579-Karoo-OS-In-Ride-Drawer-Tabs)

## 扩展能接到什么、能发出什么

- 扩展可在 `extension_info.xml` 声明 `<BonusAction actionId="…" displayName="…" />`。用户把控制器按键配置到此动作后，系统调用 `KarooExtension.onBonusAction(actionId)`。这个回调从 1.1.7 起提供，参数只有**已配置的动作 ID**；它不是通用 AXS 原始按键信号，也不携带当前页面或抽屉状态。[`onBonusAction` API](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.extension/-karoo-extension/on-bonus-action.html)、[官方 XML 样例](https://github.com/hammerheadnav/karoo-ext/blob/master/app/src/main/res/xml/extension_info.xml#L32-L38)、[官方回调样例](https://github.com/hammerheadnav/karoo-ext/blob/master/app/src/main/kotlin/io/hammerhead/sampleext/extension/SampleExtension.kt#L231-L254)
- 扩展可通过 `KarooSystemService.dispatch(PerformHardwareAction.TopRightPress)` 模拟右上角实体键；该 effect 是**让 Karoo 按实体键处理**，而不是“无条件翻骑行页”。此外，`DrawerActionComboPress` 模拟底部两键同时按下。`dispatch` 的布尔结果表示向系统发送 effect 的调用结果，不能当作抽屉状态或动作已完成的确认。[`PerformHardwareAction` 类型与说明](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-perform-hardware-action/index.html)、[`DrawerActionComboPress`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-perform-hardware-action/-drawer-action-combo-press/index.html)、[`KarooSystemService.dispatch`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext/-karoo-system-service/index.html)
- `RideState` 可区分 `Idle`、`Recording`、`Paused`，但只表达**骑行记录**状态：`Idle` 包含尚未开始或已经结束，不能说明当前处于主屏幕还是已进入但尚未开始记录的骑行界面；`Recording` 也不能说明当前可见的是数据页、抽屉还是其他界面。`ActiveRidePage` 给可见骑行页面，却不包含抽屉展开状态。[`RideState`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-ride-state/index.html)、[`ActiveRidePage`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-active-ride-page/index.html)
- 公开的 `KarooEvent` 完整继承类列表中**没有抽屉开/半开/全屏状态事件，也没有通用前台界面/焦点事件**；`KarooEffect`/`PerformHardwareAction` 也没有幂等的 `CloseDrawer`。这是对 1.1.9 公开 API 的判断，不等于断言 Karoo OS 内部没有这类状态或能力。[`KarooEvent` 列表](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-karoo-event/index.html)、[`KarooEffect` 列表](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-karoo-effect/index.html)、[`PerformHardwareAction` 列表](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-perform-hardware-action/index.html)

## 对三个场景逐一判断

1. **未进入骑行时执行右上角键：可以。** 直接使用 Karoo 的 AXS “Karoo Button - Upper Right” 映射，或把 Bonus Button 映射到扩展动作后转发 `TopRightPress`。效果由当前 Karoo 界面解释；并不是扩展能识别“未进入骑行”。[AXS 控制配置](https://support.hammerhead.io/hc/en-us/articles/25672636525979-Karoo-OS-Controlling-Karoo-with-SRAM-AXS-Controllers)、[`TopRightPress`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-perform-hardware-action/index.html)
2. **正常骑行数据页向右翻页：可以。** 同一个 `TopRightPress`/原生按键映射就让 Karoo 按骑行数据页的右键行为处理；“正在记录”不是使用此行为的必要条件。地图、菜单、弹窗和抽屉中该键可能有别的上下文效果，不能将其承诺为所有骑行时刻都翻页。[Karoo 产品手册的按键上下文](https://support.hammerhead.io/hc/en-us/article_attachments/25673969211803)、[`PerformHardwareAction`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-perform-hardware-action/index.html)
3. **抽屉开启后按一次收起：不能可靠保证。** 官方说明底部双键从关闭状态打开抽屉，再按进入全屏，再按最小化；`DrawerActionComboPress` 模拟的正是这个**循环动作**，而不是 `CloseDrawer`。由于扩展没有抽屉状态，无法判断该发一次还是两次。自维护计数也会被手势、机身键、其他动作、自动弹出的抽屉及重连打乱。抽屉全屏时，右上角键则切换抽屉标签。若把 Bonus Button 固定映射为系统自带 “Open/Close Drawer”，也不能据此推断第三方扩展获得了抽屉状态或幂等关闭命令。[骑行内抽屉操作](https://support.hammerhead.io/hc/en-us/articles/25642872519579-Karoo-OS-In-Ride-Drawer-Tabs)、[`DrawerActionComboPress`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-perform-hardware-action/-drawer-action-combo-press/index.html)、[AXS 内置动作列表](https://support.hammerhead.io/hc/en-us/articles/25672636525979-Karoo-OS-Controlling-Karoo-with-SRAM-AXS-Controllers)、[`KarooEvent` 列表](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-karoo-event/index.html)

## 建议与待测边界

若目标是**一键在主屏幕/数据页按系统默认方式向右导航**，先配置原生 “Karoo Button - Upper Right”，无需修改本应用。若“抽屉开时同一键必须收起”是硬性要求，应等待官方公开抽屉状态与明确的关闭 effect，或接受不可靠的近似行为；不要把 `RideState`、`ActiveRidePage` 或本地切换计数当作抽屉真值。可以另给 AXS 的长按/另一颗按钮单独映射系统 “Open/Close Drawer”，但这不是所问的同一按键自动上下文路由。[AXS 短按/长按与内置动作](https://support.hammerhead.io/hc/en-us/articles/25672636525979-Karoo-OS-Controlling-Karoo-with-SRAM-AXS-Controllers)、[公开事件列表](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-karoo-event/index.html)

真机仍应核对：目标 Karoo/KOS 上 AXS 映射可否选择扩展动作；首页、骑行预备页、记录中数据页、暂停、地图、抽屉半开/全屏时 `TopRightPress` 的实际结果；从触摸手势或底部组合键开抽屉后再按 Bonus Button 的效果。这些 UI 语义无法由 JVM 测试证明。[AXS 配置说明](https://support.hammerhead.io/hc/en-us/articles/25672636525979-Karoo-OS-Controlling-Karoo-with-SRAM-AXS-Controllers)、[抽屉说明](https://support.hammerhead.io/hc/en-us/articles/25642872519579-Karoo-OS-In-Ride-Drawer-Tabs)
