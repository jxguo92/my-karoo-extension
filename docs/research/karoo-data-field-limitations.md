# `karoo-ext` 制作 Data Field 的能力与限制

> 调研日期：2026-09-22。基于本项目使用的 `karoo-ext` **1.1.9** 公开 API、Hammerhead 官方帮助页和 Android 官方 `RemoteViews` 文档。本文是 [SDK 扩展能力总览](karoo-sdk-extension-capabilities.md) 的 Data Field 专题。以下“不能”均指**没有找到公开的 `karoo-ext` 契约**，不代表 Karoo OS 内部绝无私有实现，也不排除应用通过独立 Android API、自有传感器或网络取得额外数据。

## 先看结论

- 字段可以订阅 Karoo 已公开的数据类型，结合骑行、用户、导航等事件，自己计算并显示复合指标；**不能把 Karoo UI 上出现的任意信息都当作可订阅数据**。数据流按类型订阅，载荷是字段名到 `Double` 的映射和可选来源 ID，并不附带通用时间戳、单位字符串或原始传感器报文。[`OnStreamState`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-on-stream-state/index.html)、[`DataPoint`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-data-point/index.html)
- 图形字段通过 `startView` 提交 `RemoteViews`。其子视图**可用 `PendingIntent` 设计单击动作**，但 SDK 没有字段点击/长按回调；单击在 Karoo 骑行页的命中、多个热区和返回行为仍需真机验证。骑行页**长按字段**是 Karoo 自己的“更换字段”手势，不应设计为扩展的长按操作。宿主还用双击切换某些内置字段的平滑/数值图形选项，这也不是扩展可订阅的通用双击事件。[`DataTypeImpl`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.extension/-data-type-impl/index.html)、[Android `RemoteViews.setOnClickPendingIntent`](https://developer.android.com/reference/android/widget/RemoteViews#setOnClickPendingIntent(int,%20android.app.PendingIntent))、[Hammerhead 骑行中编辑说明](https://support.hammerhead.io/hc/en-us/articles/25709425315227-Karoo-OS-Editing-an-ongoing-ride)
- 格子的逻辑网格为 **60 × 60**；`gridSize=(60,15)` 表示全宽、四分之一高。`viewSize` 才是这次布局给字段的**实际像素宽高**。SDK 没有一份适用于所有设备、页面和配置的固定像素尺寸表，也没有让扩展申请最小宽高或强制占位的接口；布局由用户配置和 Karoo 决定。[`ViewConfig`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-view-config/index.html)、[Hammerhead Profile 自定义说明](https://support.hammerhead.io/hc/en-us/articles/25601814671259-Karoo-OS-Customising-Profiles)
- `ViewEmitter.updateView` **最多 1 Hz**，多余更新被丢弃。图形字段适合秒级仪表、状态、简单曲线，不适合依赖逐帧刷新、连续触摸或快速动画的 UI。[`ViewEmitter`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.internal/-view-emitter/index.html)

## 1. 能从 SDK 得到什么

**已有 Data Type 数据流。** 通过 `OnStreamState.StartStreaming(dataTypeId)` 订阅。官方 [`DataType.Type` 清单](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-data-type/-type/index.html)逐项说明每个类型包含的 [`DataType.Field`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-data-type/-field/index.html)。对复合字段尤其有用的例子：

- 运动与骑行：当前/3 秒或更长窗口的速度、功率、踏频，心率，平均/最大/单圈指标，距离、海拔、坡度、爬升、时间、功率/心率区间、训练目标等。**订阅的是具体类型，不能只凭字段名猜测所有类型都有同一字段**。[`DataType.Type`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-data-type/-type/index.html)
- 变速及设备数据：`SHIFTING_GEARS` 含前后档位及齿数等，`SHIFTING_REAR_GEAR` 含后档位、后飞轮齿数、最大档数；还有轮胎气压、eBike、悬挂、体温等类型。能否持续给出数值取决于传感器、配置及系统状态。[`DataType.Type`：Shifting、Tire Pressure 等](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-data-type/-type/index.html)、[`StreamState`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-stream-state/index.html)
- 位置与导航：`LOCATION` 类型含经纬度及可选方向、精度等；`OnLocationChanged` 另提供经纬度和可选方向。`OnNavigationState` 可给当前路线的编码 polyline、距离、名称、POI、爬坡及重新接线等信息；路程剩余、下一转弯距离等也有对应数据类型。**这不是任意查询全部已保存路线或地图底图的接口**。[`LOCATION` 数据类型](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-data-type/-type/index.html)、[`OnLocationChanged`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-on-location-changed/index.html)、[`NavigatingRoute`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-on-navigation-state/-navigation-state/-navigating-route/index.html)

**与字段计算相关的系统事件。** `RideState` 区分未骑行/录制/暂停，`Lap` 给圈次变化；`UserProfile` 提供 FTP、心率配置、分区及偏好单位；`ActiveRideProfile`/`ActiveRidePage` 给当前资料与可见页面；`SavedDevices` 给已保存设备的名称、启用状态、支持类型及可选齿比配置。`ActiveRidePage` 的元素含 `dataTypeId` 和 `gridSize`，但不提供其他字段的图像或像素布局。[`KarooEvent` 清单](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-karoo-event/index.html)、[`UserProfile`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-user-profile/index.html)、[`RideProfile.Page`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-ride-profile/-page/index.html)、[`SavedDevice`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-saved-devices/-saved-device/index.html)

**数值可靠性边界。** `StreamState` 有 `Idle`、`Searching`、`Streaming`、`NotAvailable` 四态；即使为 `Streaming`，`values` 也可能不含预期字段。`DataPoint.sourceId` 可为空。字段须分别处理断线、缺项、暂停、重置，不能把上次值永久当作当前值。[`StreamState`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-stream-state/index.html)、[`DataPoint`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-data-point/index.html)

### 公开接口没有提供的常见信息

- **任意底层传感器数据**：`DataPoint` 没有原始 BLE/ANT 报文、采样时间、信号强度或通用质量字段；`SavedDevices` 是系统保存的设备摘要，并非对系统已连接设备的原始通信句柄。若某个现成类型公开了专门的质量字段，应按该类型单独判断。以上是公开数据结构的边界判断。[`DataPoint`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-data-point/index.html)、[`SavedDevice`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-saved-devices/-saved-device/index.html)、[`DataType.Field`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-data-type/-field/index.html)
- **通用触摸、实体按键和变速按钮输入事件**：`KarooEvent` 清单没有这些事件。`PerformHardwareAction` 是向系统**模拟**按键，不是读取按键；Bonus Action 是单独声明和调用的扩展动作，不能等同于收到所有按钮原始输入。[`KarooEvent`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-karoo-event/index.html)、[`PerformHardwareAction`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-perform-hardware-action/index.html)、[`KarooExtension`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.extension/-karoo-extension/index.html)
- **内置手机媒体字段的数据与控制**：公开类型/字段及事件/效果清单没有手机正在播放的歌曲、播放状态、手机音量或播放/切歌命令；详见[媒体控制专题](karoo-media-controls-data-field.md)。这仅限 `karoo-ext`，不否定自建手机伴侣应用的可能。[`DataType.Type`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-data-type/-type/index.html)、[`KarooEvent`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-karoo-event/index.html)、[`KarooEffect`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-karoo-effect/index.html)
- **Karoo 当前字段的最终字体颜色/完整主题 token**：`ViewConfig` 给对齐、边框等设置，却不给当前文字色或背景色。图形字段应自己决定亮暗配色；已有[社区实现抽样](karoo-sdk-extension-capabilities.md#社区扩展如何处理图形字段的日夜文字色)，但运行中主题切换是否自动刷新仍须真机测。[`ViewConfig`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-view-config/index.html)

## 2. 点击、长按与能触发的效果

`DataTypeImpl.startView(context, config, emitter)` 只提供**输出**视图/视图事件的入口，没有 `onClick`、`onLongClick` 或手势流。Android `RemoteViews.setOnClickPendingIntent(viewId, pendingIntent)` 可以给根视图或支持的子视图设置单击热区，让点击进入本应用的 `BroadcastReceiver`、`Service` 或 `Activity`；收到后可切换本地显示状态、打开本应用设置页，或使用 `KarooSystemService.dispatch` 发 SDK 允许的效果，例如圈次、暂停/恢复、蜂鸣、骑行提醒、切到地图页/缩放等。**这些动作来自点击后应用逻辑，并非 Data Field 特有的 SDK 点击回调。** Karoo 宿主是否在骑行页将每个子视图单击都交给 `PendingIntent`，以及 Activity 弹出体验，需要目标机型验证。[`DataTypeImpl`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.extension/-data-type-impl/index.html)、[`RemoteViews.setOnClickPendingIntent`](https://developer.android.com/reference/android/widget/RemoteViews#setOnClickPendingIntent(int,%20android.app.PendingIntent))、[`KarooEffect`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-karoo-effect/index.html)

上述点击路径依赖**自定义图形视图**；仅用 `startStream` 的标准数字字段由 Karoo 绘制，扩展没有其内部子视图可绑定 `PendingIntent`。[`DataTypeImpl`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.extension/-data-type-impl/index.html)

`RemoteViews` 的公开方法没有普通 `setOnLongClick...`，SDK 的 `ViewEvent` 也仅包含图形配置、数值配置和自定义流状态。Hammerhead 的骑行交互说明明确把字段长按用于打开字段选择器；因此**不要承诺长按可作为扩展按钮**。同样，系统文档描述的双击切换内置字段选项，不应推断为扩展收到双击回调。[Android `RemoteViews` 方法清单](https://developer.android.com/reference/android/widget/RemoteViews)、[`ViewEvent`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-view-event/index.html)、[Hammerhead 骑行中编辑说明](https://support.hammerhead.io/hc/en-us/articles/25709425315227-Karoo-OS-Editing-an-ongoing-ride)

## 3. 格子尺寸与空间申请

`ViewConfig` 是**宿主交给扩展的结果**：`gridSize` 是列跨度×行跨度（60 为全宽/全高），`viewSize` 是当前格子的宽×高**像素**，`textSize` 是同格标准数字字段字号（sp）；另有 `alignment`、`boundariesEnabled`、`preview`。例如 `(60,15)` 只说明占整页宽度的四分之一高度，**不能换算成某个固定的 px 值**。页面是数据页还是地图页、字段个数与位置、半宽/全宽、Karoo 型号及系统布局均可能改变最终尺寸。Hammerhead 明确说布局会随字段数量自动排版，半宽字段可能少显示信息。[`ViewConfig`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-view-config/index.html)、[Profile 自定义说明](https://support.hammerhead.io/hc/en-us/articles/25601814671259-Karoo-OS-Customising-Profiles)

**没有官方固定尺寸清单，也没有申请空间的公开 API。** `extension_info.xml` 的 `DataType` 声明只有字段 ID、名称、说明、图形标志和图标；`DataTypeImpl.startView` 只有传入的 `ViewConfig` 与 emitter；`ViewEvent` 不能要求最小格、跨格、全屏或调整页面其他字段。这是对这组公开签名的推断，不是 Karoo 页面算法的内部说明。[官方 README 的 XML 示例](https://github.com/hammerheadnav/karoo-ext)、[`DataTypeImpl`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.extension/-data-type-impl/index.html)、[`ViewEvent`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-view-event/index.html)

因此“格子的实际值”应在真机每次 `startView` 记录 `hardwareType / KOS 版本 / 页面类型 / preview / gridSize / viewSize / textSize`，再统计本项目需要支持的最小宽高。不要只按 `(60,15)` 画一张固定大小的图；也不要把 `viewSize` 当作 dp。Hammerhead 曾在 1.535.2029 的扩展更新中修复 `ViewConfig` 尺寸总为 `(0,0)` 的问题，旧 KOS 若仍要支持，应给非正尺寸准备保守布局。[`ViewConfig`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-view-config/index.html)、[Hammerhead 1.535.2029 发布说明](https://support.hammerhead.io/hc/en-us/community/posts/32649390375835-New-Extension-Capabilities-in-Karoo-Release-1-535-2029)

## 4. 渲染格子的限制

1. **两种显示模式。** 普通数字字段由 `startStream` 发 `StreamState`，Karoo 负责标准数值外观；若有 `Field.SINGLE`，`UpdateNumericConfig(formatDataTypeId)` 可让 Karoo 按匹配的内置类型处理精度与单位。自定义图形字段在 XML 标记 `graphical="true"`，由 `startView` 发送 `RemoteViews`。`UpdateGraphicConfig` 可控制是否显示字段图标/名称，以及单值格式类型；`ShowCustomStreamState` 可在标准流容器显示替代消息及颜色。它们都不负责分配格子尺寸。[`DataTypeImpl`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.extension/-data-type-impl/index.html)、[`UpdateNumericConfig`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-update-numeric-config/index.html)、[`UpdateGraphicConfig`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-update-graphic-config/index.html)、[`ShowCustomStreamState`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-show-custom-stream-state/index.html)
2. **`RemoteViews` 不是普通 Android View 树。** 它在 Karoo 进程膨胀，只支持 Android 白名单中的布局/控件和允许的远程更新方法，不能直接放任意自定义 `View`、`WebView` 或常规 Compose 交互界面。可用 XML 布局及 `TextView`、`ImageView`、`ProgressBar` 等；复杂图形可以在扩展进程预绘为位图交给 `ImageView`，但应控制位图和跨进程传输开销。Glance 是生成 `RemoteViews` 的可选写法，不会取消这些宿主限制。[官方 README：跨进程视图与可选 Glance](https://github.com/hammerheadnav/karoo-ext)、[Android `RemoteViews` 支持列表](https://developer.android.com/reference/android/widget/RemoteViews)
3. **画面更新节奏。** `updateView` 最多 1 Hz，超频的视图提交被丢弃；数据流的更新率不等同于视图更新率。多个原始流先合并/采样为最新状态，再最多每秒提交一帧；点击后的图形反馈也要按这一限制设计。`RemoteViews` 本身允许 `Chronometer` 等宿主运行的控件，但这些控件在 Karoo 字段内的显示效果仍需实测。[`ViewEmitter`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.internal/-view-emitter/index.html)、[Android `RemoteViews` 支持列表](https://developer.android.com/reference/android/widget/RemoteViews)
4. **宿主外观与预览。** `ViewConfig.preview=true` 表示页面编辑预览；预览应使用固定可复现数据。文字对齐、边界设置、标题显示需根据 `ViewConfig`/`UpdateGraphicConfig` 处理，不能假设页面主题颜色会自动传入。字段视图与数据流各有取消生命周期，取消时应终止订阅/协程，避免换页或重入后残留刷新。[`ViewConfig`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-view-config/index.html)、[`UpdateGraphicConfig`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-update-graphic-config/index.html)、[`DataTypeImpl`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.extension/-data-type-impl/index.html)

## 对本项目的直接含义与待测项

- 现有 `CompositeFieldView.isWide` 以 `gridSize.first == 60` 判断**全宽逻辑格**，这个判断符合 SDK 的 60 列网格，但不代表图形拥有固定像素宽度，也没有考虑高度。以后做密集仪表盘，应同时按 `viewSize.first/second` 和 `preview` 决定内容层级；过窄/过矮时主动隐藏次要指标，而不是指望字段强制占更大空间。[本项目实现](../../app/src/main/kotlin/com/jxguo92/mykarooextension/core/ui/CompositeFieldView.kt)、[`ViewConfig`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-view-config/index.html)
- 在 Karoo 2/新 Karoo 的实际 KOS 版本上，分别记录数据页和地图页的全宽/半宽、少字段/多字段格子的 `gridSize` 与 `viewSize`；检查标题/边框开关、日夜切换、预览和 `NotAvailable` 时的裁切与可读性。**本文没有真机尺寸样本，因此不提供伪造的 px 对照表。**
- 若要做可点击字段，先用一个根热区和两个子热区验证单击是否到达、长按是否进入系统字段选择器、快速连点是否重复触发，以及切页/重新进入后是否出现失效 `PendingIntent`。多按钮操作在真机验证前属于可行方案，不是已确认的 Karoo 交互保证。
