# 官方 `karoo-ext` SDK 的扩展能力

> 调研日期：2026-09-22。范围：Hammerhead 官方 [`karoo-ext` 1.1.9 API 文档](https://hammerheadnav.github.io/karoo-ext/index.html)、[官方仓库 README](https://github.com/hammerheadnav/karoo-ext) 与[官方发布记录](https://github.com/hammerheadnav/karoo-ext/releases)。本文描述公开 SDK 契约，不把 Android 平台本身的能力算作 `karoo-ext` 能力。本项目的 `gradle/libs.versions.toml` 当前锁定 1.1.9。

Data Field 的数据可用性、点击/长按、格子尺寸和渲染限制见[专题调研](karoo-data-field-limitations.md)。

## 总览

`karoo-ext` 是供 Karoo 上 Android 应用使用的库。应用既可用 `KarooSystemService` 订阅 Karoo 事件、发送效果，也可注册继承 `KarooExtension` 的 Android `Service`，通过 Manifest intent filter 和 `extension_info.xml` 向系统声明扩展能力。扩展代码运行在自己的应用进程；跨进程图形视图以 Android `RemoteViews` 传递。官方样例使用 Compose、Hilt、ViewModel 和 Glance，但它们都不是 SDK 的必需依赖。[官方 README：Getting started、Methodologies](https://github.com/hammerheadnav/karoo-ext)

| 入口 | 官方公开能力 | 主要接口 |
| --- | --- | --- |
| 系统交互 | 订阅骑行、数据流、导航、资料等事件；发送骑行、通知、屏幕等效果 | [`KarooSystemService`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext/-karoo-system-service/index.html)、[`KarooEvent`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-karoo-event/index.html)、[`KarooEffect`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-karoo-effect/index.html) |
| 扩展注册 | 静态 Data Type、Bonus Action，以及设备扫描、地图层、FIT 写入开关 | [`KarooExtension`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.extension/-karoo-extension/index.html)、[`ExtensionInfo`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-extension-info/index.html) |

## Data Field 与数据读取

- `ExtensionInfo` 的 `dataTypes` 来自 XML，包含 `typeId`、名称、说明、`graphical` 和图标；`KarooExtension.types` 提供对应的 `DataTypeImpl` 实现。`startStream` 发送 `StreamState`，数值字段需要它，若自定义视图或其他字段要消费该字段数据也需要它。`startView` 发送 `ViewEvent` 和 `RemoteViews`；更新 `RemoteViews` 时应将 XML 的 `graphical` 设为 `true`。[`DataTypeImpl`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.extension/-data-type-impl/index.html)、[`KarooExtension`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.extension/-karoo-extension/index.html)
- `StreamState` 有 `Idle`、`Searching`、`Streaming(DataPoint)`、`NotAvailable` 四态；`DataPoint` 包含数据类型 ID、数值字段映射和可选来源 ID。`ViewConfig` 提供网格/视图尺寸、文字大小、对齐和 `preview`；视图事件可调整图形/数值格式或显示自定义状态消息。[`StreamState`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-stream-state/index.html)、[`DataPoint`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-data-point/index.html)、[`ViewConfig`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-view-config/index.html)、[`ViewEvent`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-view-event/index.html)
- 系统已有数据通过 `addConsumer(OnStreamState.StartStreaming(dataTypeId))` 读取。官方生成的 [`DataType.Type`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-data-type/-type/index.html) 与 [`DataType.Field`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-data-type/-field/index.html) 列出可引用的既有类型和字段，包括速度、功率、心率、踏频、爬坡、导航及变速数据；具体类型的字段组合以这两份列表为准。订阅结果仍须处理四种流状态，不能假定每个类型始终有数值。[`OnStreamState`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-on-stream-state/index.html)、[`StreamState`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-stream-state/index.html)
- 图形字段的 `ViewEmitter.updateView` 最多按 **1 Hz** 接收更新；更频繁的视图提交会被丢弃。这是视图更新限制，不是所有系统数据流的速率说明。[`ViewEmitter`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.internal/-view-emitter/index.html)

## 系统事件与主动效果

`KarooEvent` 的公开子类覆盖：`RideState`、`Lap`、`OnStreamState`、`UserProfile`、`OnHttpResponse`、`OnLocationChanged`、`OnGlobalPOIs`、`OnNavigationState`、`OnMapZoomLevel`、`SavedDevices`、`Bikes`、`ActiveRideProfile` 和 `ActiveRidePage`。导航状态含空闲、按路线导航、前往目的地三类，并可提供路线 polyline、爬坡和 POI 等信息。[`KarooEvent` 完整子类清单](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-karoo-event/index.html)、[`NavigationState`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-on-navigation-state/-navigation-state/index.html)

`KarooEffect` 的公开子类可标记圈、暂停/恢复骑行、播放蜂鸣、模拟机身按键、开关屏幕、申请/释放蓝牙与 ANT 无线电、设置启动器背景、切到地图页/缩放、打开地图落点，以及显示通知或骑行提醒。`SystemNotification` 加入 Control Center 并可配置点击后启动 Activity；`InRideAlert` 用于当前骑行的重要提醒。`PerformHardwareAction` 是**模拟**四个机身按键及两种组合键，不是接收这些按键的事件。[`KarooEffect` 完整子类清单](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-karoo-effect/index.html)、[`SystemNotification`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-system-notification/index.html)、[`InRideAlert`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-in-ride-alert/index.html)、[`PerformHardwareAction`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-perform-hardware-action/index.html)

HTTP 请求不是 `KarooEffect`：以 `OnHttpResponse.MakeHttpRequest(method, url, headers, body, waitForConnection)` 参数注册 consumer，接收 `Queued`、`InProgress`、`Complete`。系统优先用 Wi-Fi，受支持时可经蓝牙转发到 companion app。官方建议上传/下载少于 100 KB，并限于与当前骑行重要相关的请求；不宜据此设计大文件传输。[`OnHttpResponse`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-on-http-response/index.html)、[`HttpResponseState`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-http-response-state/index.html)

## 地图、FIT、设备与 Bonus Action

- **地图层**：XML 声明 `mapLayer`，`KarooExtension.startMap` 发出 `MapEffect`。公开效果为 `ShowSymbols`/`HideSymbols` 与 `ShowPolyline`/`HidePolyline`，支持 POI/图标和带颜色、宽度的编码折线。这是对 Karoo 地图的覆盖层接口；文档没有提供接管底图渲染的接口。[`ExtensionInfo`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-extension-info/index.html)、[`KarooExtension`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.extension/-karoo-extension/index.html)、[`MapEffect`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-map-effect/index.html)、[`Symbol`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-symbol/index.html)
- **FIT 写入**：XML 声明 `fitFile`，`startFit` 发出 `FitEffect`，用于扩充每次骑行记录的 FIT 文件。公开类型包括写入记录消息（文档注明 1 Hz）、最终 Session 消息、Event 消息，以及自描述开发者字段；其中开发者 ID/字段描述消息由 Karoo System 内部处理。[`ExtensionInfo`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-extension-info/index.html)、[`FitEffect`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-fit-effect/index.html)、[`FitEffectWithValues`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-fit-effect-with-values/index.html)、[`DeveloperField`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-developer-field/index.html)
- **设备接入**：XML 声明 `scansDevices` 后，可通过 `startScan` 产生 `Device`（UID、名称、支持的数据类型），再由 `connectDevice(uid, emitter)` 回报连接状态、电池、厂家信息与数据点。无线电申请效果仅负责请求蓝牙/ANT 开启；具体外设通信协议仍需扩展自行实现。[`KarooExtension`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.extension/-karoo-extension/index.html)、[`Device`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-device/index.html)、[`DeviceEvent`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-device-event/index.html)、[`RequestBluetooth`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-request-bluetooth/index.html)
- **Bonus Action**：XML 中的 `BonusAction(actionId, displayName)` 由 Karoo 调用 `onBonusAction(actionId)`；它是扩展暴露的动作入口。官方 API 并未说明它等同于接收所有实体按键或 SRAM 换挡按钮事件。[`ExtensionInfo`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-extension-info/index.html)、[`KarooExtension`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.extension/-karoo-extension/index.html)

## 生命周期与版本边界

`KarooSystemService` 提供 `connect`、`connected`、`addConsumer`、`removeConsumer`、`dispatch` 和 `disconnect`；`disconnect` 会注销全部 consumer。`Emitter` 可设置取消回调；字段 stream/view、地图、FIT 和设备等订阅应在取消回调中结束对应任务，并在所属 Android 组件销毁时断开系统连接。[`KarooSystemService`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext/-karoo-system-service/index.html)、[`Emitter`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.internal/-emitter/index.html)、[`DataTypeImpl` 取消示例](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.extension/-data-type-impl/index.html)

官方 Dokka 当前标记 **1.1.9**，而 GitHub 发布页将 **1.1.8** 标为 Latest、1.1.9 标为 pre-release；本项目已选 1.1.9，因此本文按 1.1.9 API 描述。文档注明地图效果/导航状态始于 **1.1.3**，FIT 效果始于 **1.1.4**，应用 manifest 契约始于 **1.1.1**。1.1.8 发布说明称该版能力在 Karoo 与 K2 的 KOS **1.613.2351+** 可用；不能据此直接推断所有 1.1.9 新增能力在相同 KOS 版本均可用，实际部署须按目标设备测试。[API 首页](https://hammerheadnav.github.io/karoo-ext/index.html)、[发布页](https://github.com/hammerheadnav/karoo-ext/releases)、[`MapEffect`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-map-effect/index.html)、[`FitEffect`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-fit-effect/index.html)、[`KarooAppManifest`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-karoo-app-manifest/index.html)

SDK 还定义可由 Manifest 元数据提供的 `KarooAppManifest`，用于 APK URL、版本、图标、截图等安装/更新展示信息；官方 1.1.1 发布说明特别指出当时 companion app 尚不支持此 manifest。发布机制与设备功能 API 应分别验证。[`KarooAppManifest`](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-karoo-app-manifest/index.html)、[发布页 1.1.1 说明](https://github.com/hammerheadnav/karoo-ext/releases)

## 未证实的能力

以下是依据 1.1.9 **公开接口清单**作出的边界判断，而非对 Karoo OS 内部实现的断言：`KarooEvent` 没有通用实体按键或 SRAM 按钮输入事件；`KarooEffect` 有模拟按键与 Control Center 通知，却没有注册 Control Center 自定义开关/控件的效果；设备扫描/连接接口也不等同于获取系统已配对设备的原始按钮报文。因此，若需求涉及这些输入或控件，应先做真机验证或查找新的官方接口，不能将现有 API 名称当作支持证据。[`KarooEvent` 子类清单](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-karoo-event/index.html)、[`KarooEffect` 子类清单](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-karoo-effect/index.html)、[`DeviceEvent` 子类清单](https://hammerheadnav.github.io/karoo-ext/karoo-ext/io.hammerhead.karooext.models/-device-event/index.html)

## 社区扩展如何处理图形字段的日夜文字色

以下是对 [awesome-karoo](https://github.com/timklge/awesome-karoo) 收录的三个开源扩展的抽样核对，属于**社区实现与作者经验**，不是官方 SDK 对主题同步的保证。Headwind 的链接锁定到所检查的提交；Barberfish、KSafe 的实现说明链接目前指向仓库分支，可能随上游更新而变化。

- **karoo-headwind**：图形字段使用 Glance `TextStyle(color = ColorProvider(Color.Black, Color.White))`，箭头 tint 也传入日间黑色、夜间白色；背景则以 `background(dayColor, nightColor)` 指定两套颜色。错误文字同样采用双色 `ColorProvider`。这是由扩展显式给出颜色对，由 Glance 按配置解析，不是读取 Karoo 提供的“当前字体色”。[HeadwindDirectionView.kt（固定提交）](https://github.com/timklge/karoo-headwind/blob/c8410ad0dc89b02dbc66b0053e7473611ec79ddc/app/src/main/kotlin/de/timklge/karooheadwind/datatypes/HeadwindDirectionView.kt)、[Views.kt（固定提交）](https://github.com/timklge/karoo-headwind/blob/c8410ad0dc89b02dbc66b0053e7473611ec79ddc/app/src/main/kotlin/de/timklge/karooheadwind/datatypes/Views.kt)
- **Barberfish**：作者的架构说明写明，`BarberfishView` 读取 Android `Configuration.UI_MODE_NIGHT_MASK`，将 `isNightMode` 交给颜色计算；文字色、标题色、图标 tint 和背景组成 `ColorConfig`，图形字段渲染时应用这些值。彩色文字另有针对亮/暗背景的两套调色板；色块模式按色块对比度选黑字或白字。证据是维护者的[架构与颜色系统说明](https://github.com/jpweytjens/Barberfish/blob/master/docs/architecture.md#color-system)，并非本次逐行核对的 Kotlin 源码。[README](https://github.com/jpweytjens/Barberfish) 也明确宣称支持亮暗模式。
- **Karoo-KSafe**：作者的[字段颜色实现说明](https://github.com/lockevod/Karoo-KSafe/blob/main/docs/field-colours.md#karoo-theme-text-colour-implementation-note)明确写明：默认透明背景的字段在**每次渲染**时读 Android `Configuration.UI_MODE_NIGHT_MASK`，夜间设白字、日间设黑字。文档还记录了真机反馈：布局里的 `?android:attr/textColorPrimary` 曾在白色字段上解析出白字，因此改为显式设色。这是维护者记录的设备经验，不等于所有 Karoo 固件或所有主题属性都如此。

这三个实现都由扩展自己指定文字色：双色 Glance `ColorProvider`，或读取 Android `uiMode` 后计算并设置颜色。所核对材料没有发现官方 SDK 直接返回当前 Karoo 字体颜色的接口。**运行中从 light 切到 dark 是否立即更新既有 `RemoteViews`**，上述源码与说明尚不足以证实：需要在 Karoo 2/3 上分别切换骑行页面主题、观察扩展进程的 `uiMode` 与字段重绘；如颜色在切换后不刷新，扩展须在配置变化时重新提交视图。
